# Shared protocol vectors

Generated by `python scripts/gen-protocol-vectors.py docs/protocol-test-vectors`
from the Python reference (`scripts/terra_protocol.py`). Do not edit by hand;
change the generator and regenerate. CI regenerates and diffs this folder.

Consumers:

- C firmware codec: `firmware/tests/test_protocol.c` (run by `scripts/test-host.ps1`).
- Rust companion codec: `companion/crates/protocol/tests/vectors.rs` (`cargo test`).

Each vector has `<name>.bin` (raw bytes) and `<name>.json` (human description).
`manifest.tsv` is the machine-readable index, one tab-separated line per vector:

| kind | `.bin` content | fields after `name kind expect` |
| --- | --- | --- |
| `media_state` | payload | playback, position, duration, source/title/artist/album as hex (`-` = empty) |
| `volume_state` | payload | volume, muted |
| `media_command` | payload | command, value |
| `hello` | payload | version, major, minor, patch, capabilities |
| `hello_ack` | payload | version, major, minor, patch, status |
| `device_status` | payload | version, major, minor, patch, link, flags, rx_errors |
| `error` | payload | code, related_type, related_seq |
| `artwork_begin` | payload | id, format, width, height, size (V2) |
| `artwork_chunk` | payload | id, offset, data hex (V2) |
| `artwork_end` | payload | id, crc32 (V2) |
| `crc32` | data | CRC-32/ISO-HDLC of the data, decimal (no re-encode) |
| `fragment` | packets, each prefixed by u16 LE length | type, seq, mtu, payload hex |
| `stream` | records: u16 LE length, u32 LE time_ms, packet | per packet `drops/status`, `;`-separated |

`expect` is `ok` or `malformed`. For `ok` payload vectors, implementations must
decode to the listed fields **and** re-encode to identical bytes. In `stream`
results, `drops` is `-` or drop reasons joined by `+`, and `status` is `-` or
`type:seq:payload` in hex for a completed message.
